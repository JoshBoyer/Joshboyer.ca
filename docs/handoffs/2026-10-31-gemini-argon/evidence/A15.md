## 6. Assumptions and Risks Accepted

1. **Reconciling Live Stack Architecture (`RestApi` / `State` / `Evidence`) with Brief Shorthand:** Per `user_global` §1 ("Current code and tests win over documents") and `A02.md`/`A03.md`, the deployed `PortfolioChatDev` stack in `us-east-2` uses `apigateway.RestApi` (`Api` with stage `dev`), `dynamodb.Table` (`State`), and `s3.Bucket` (`Evidence`), and `services/chat/src/config.ts` (`A06`) validates `MCP_ENDPOINT_URL` against `/^https:\/\/[a-z0-9]{10}\.execute-api\.us-east-2\.amazonaws\.com\/dev\/api\/chat\/_mcp$/`. Adding `POST /api/chat/_mcp` with `apigateway.AuthorizationType.IAM` (`AuthorizationType: 'AWS_IAM'`) on `Api` preserves all deployed logical IDs, streaming routes, and `config.ts` compatibility.
2. **Avoiding CloudFormation Circular Dependency Between `Handler` and `ApiDeploymentStage`:** Calling `api.urlForPath('/api/chat/_mcp')` or `api.arnForExecuteApi(..., api.deploymentStage.stageName)` inside `Handler` environment variables creates a CloudFormation cycle (`Handler -> ApiDeploymentStagedev -> ApiDeployment -> Method -> Handler`). Constructing `https://${api.restApiId}.execute-api.${REGION}.amazonaws.com/dev/api/chat/_mcp` and `arn:${this.partition}:execute-api:${REGION}:${this.account}:${api.restApiId}/dev/POST/api/chat/_mcp` binds directly to `Api` (`Ref: Api`) with zero cyclic dependencies.
3. **PassThrough Tracing Without Wildcard X-Ray IAM Policy:** Setting `(mcpHandler.node.defaultChild as lambda.CfnFunction).tracingConfig = { mode: 'PassThrough' }` synthesizes `TracingConfig: { Mode: 'PassThrough' }` on `McpFunction` without CDK auto-attaching `xray:PutTraceSegments`/`xray:PutTelemetryRecords` on `Resource: '*'` to `McpRole`.
4. **Public Access & Voice Disabled:** `PUBLIC_CHAT_ENABLED: 'false'` and `PROBE_ENABLED: 'false'` remain strictly enforced.
